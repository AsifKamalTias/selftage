## Project

Selftage is an offline-first personal income and expense tracker: Expo SDK 57 (React Native 0.86, React 19.2, TypeScript strict), running on iOS, Android and web from one codebase. All data lives on the device in SQLite — there is no backend. Expo APIs changed in SDK 57, so check the versioned docs in AGENTS.md rather than relying on memory.

## Commands

```bash
npm install
npm start                       # dev server (a / i / w to open Android / iOS / web)
npm run android                 # expo start --android
npm run web                     # expo start --web
npm run typecheck               # tsc --noEmit
npm run lint                    # eslint via expo lint
npm test                        # jest (jest-expo preset)
npm test -- src/lib             # one folder
npm test -- -t "budgetHealth"   # one test by name
npm run format                  # prettier --write .
```

`/ios` and `/android` are gitignored (Continuous Native Generation). Change native config in `app.json` via config plugins, never in generated folders.

### Typed routes on Windows

`.expo/types/router.d.ts` is generated by the dev server. Its file watcher has a Windows bug (it checks `startsWith('../')` against a `..\` path), so while a dev server runs it adds non-route files as routes and drops real ones, and `npm run typecheck` then reports bogus errors on `router.push(...)` calls. Restarting the dev server regenerates the file correctly. To fix it without a server:

```bash
node -e "const p=require('path');const c=p.resolve('node_modules/expo/node_modules/@expo/cli/build/src/start/server/type-generation/routes.js');const m=require.resolve('@expo/router-server/build/typed-routes',{paths:[p.dirname(c)]});process.env.EXPO_ROUTER_APP_ROOT=p.resolve('src/app');require(m).regenerateDeclarations(p.resolve('.expo/types'),{})"
```

## Architecture

Layers, from the bottom up: `src/db` (schema, migrations, query hooks) → `src/features/*` (repository → service → hooks → components, one folder per domain) → `src/app` (routes only) with `src/components` (design system + charts), `src/theme` and `src/lib` shared across.

- **Routing:** expo-router; routes live in `src/app` (not `app/`). `(tabs)` holds the four tab screens; everything else is a stack screen registered in `src/app/_layout.tsx`. Typed routes and the React Compiler are enabled in `app.json`, so manual `useMemo`/`useCallback` is rarely needed.
- **Data access:** repositories are plain functions taking `SQLiteDatabase` and returning domain types from `src/db/types.ts`; SQL aliases snake_case columns to camelCase so no mapping layer exists. Screens never call repositories directly — they use `useDbQuery` / `useInfiniteDbQuery` / `useDbMutation` from `src/db/hooks.ts`. Every mutation invalidates the whole `['db']` key; the data is local, so refetching is cheaper than tracking dependencies.
- **Services** (`features/*/service.ts`) exist where a write spans more than the database — transactions persist attachment files first, then insert, then clean up on failure.
- **Money:** integers in hundredths everywhere (`src/lib/money.ts`), never floats. The display currency only affects formatting; stored values are never converted.
- **Dates:** local calendar strings `YYYY-MM-DD` for anything a user picks; ISO timestamps for `created_at` / `updated_at`. Week-dependent ranges take the `weekStartsOn` setting — pass it, don't assume Monday.
- **Ledger invariant:** every transaction writes exactly one `ledger_entries` row in the same database transaction (income = debit, expense = credit); accounts with an opening balance get an `opening` entry that always sorts first. Running balances come from a SQL window function over the account scope, so they stay correct under filtering and pagination.
- **Budgets:** one limit per scope (overall or one expense type) per period. Status is computed against the current period window (`features/budgets/period.ts`); `budgetHealth` is the single source of truth for ok / warning / exceeded. Saving a transaction snapshots budget health before and after the write, so a crossing is announced once instead of on every later transaction.
- **Migrations** (`src/db/migrations.ts`) are append-only and run inside a transaction with their version bump. Never edit a shipped migration; add the next version.
- **Errors:** repositories throw `DomainError` with user-facing text. SQLite on web reports constraint violations only as a generic failure, so uniqueness and in-use checks are done in code (`assertUniqueName`), not left to the database.
- **Platform splits:** Metro picks `*.web.ts(x)` over the base file — attachments storage (document directory vs data URLs), opening files, date field, and file sharing/printing. Change both sides together.
- **Web specifics:** `web.output` is `single`; SQLite needs cross-origin isolation, which `metro.config.js` adds in dev and the expo-router plugin headers add in production.

Naming: a "category" in code is a **type** in the UI (income/expense type). "Catalog" covers the two user-managed lists that share a shape, categories and sources.

## Conventions

- Screens stay thin: layout plus feature components; logic belongs in `features/`.
- Use the design system in `src/components/ui` and tokens from `src/theme/tokens.ts`; no ad-hoc colors or spacing.
- Reanimated shared values use `.get()` / `.set()` (React Compiler compatible), and `scheduleOnRN` from `react-native-worklets` rather than `runOnJS`.
- Tests cover pure logic (money, dates, budget periods, chart maths). Anything needing SQLite is verified by running the app.
- `npx expo install <pkg> -- --save-dev` still records dev dependencies under `dependencies`; move them by hand.
